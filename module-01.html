01 · OPERATIONAL GOVERNANCE

The Cybersecurity Mission & Scope Boundaries

Security testing is defined by legal, technical, and ethical authorization. A technical action without authorized scope is an attack; the same action within defined scope is assurance.

01 · AUTHORIZATION

Rules of Engagement (RoE)

Explicit written authorization detailing IP ranges, test timeframes, out-of-scope targets (e.g. production DBs, 3rd-party SaaS), and emergency contacts.

02 · TRUST BOUNDARIES

Defining the Perimeter

A trust boundary is where data transitions between different trust levels (e.g., untrusted Internet to DMZ, or student host to training lab).

03 · EVIDENCE INTEGRITY

Defensible Observations

Every observation must be timestamped, reproducible, and clearly separated into raw data, technical interpretation, and business impact.

02 · CORE SECURITY OBJECTIVES

The CIA Triad & Extended Security Pillars

Every security control, incident, policy, and tool ultimately protects or restores one or more of these core pillars.

CONFIDENTIALITY

Protecting Secrecy

Ensuring data is accessible ONLY to authorized entities. Breached by unauthorized disclosure, sniffing, or credential theft.

Controls: TLS, AES-256, ACLs, MFA
INTEGRITY

Protecting Accuracy

Ensuring information and systems are authentic, complete, and uncorrupted. Breached by tampering, MITM, or unauthorized changes.

Controls: SHA-256, Digital Signatures, WORM
AVAILABILITY

Protecting Access

Ensuring systems, networks, and applications are reliably accessible when needed. Breached by DDoS, ransomware, or hardware failure.

Controls: Redundancy, Backups, Load Balancers

03 · QUANTITATIVE REASONING

Assets, Threats, Vulnerabilities & Risk

Risk does not exist in isolation. It is the calculated likelihood and impact of a threat exploiting a vulnerability on an asset.

05 · RESIDUAL RISKDecision signal
ASSET: What we are protecting (e.g. Customer database, API keys, Domain Controllers). Value dictates the maximum potential loss.
THREAT: Any entity or event with potential to cause harm (e.g. Nation-state APT, insider, script kiddie, hardware outage).
VULNERABILITY: A weakness in software, hardware, configuration, or human process (e.g. unpatched CVE-2024-XXXX, default password).
CONTROLS: Layered countermeasures that reduce likelihood or impact (e.g. MFA, WAF, network segmentation, immutable backups).
RESIDUAL RISK: The remaining risk after controls are applied: Inherent Risk - Control Effectiveness = Residual Risk.
04 · ARCHITECTURAL STRATEGY

Defense in Depth & Layered Countermeasures

No single security control is infallible. Defense in depth ensures that if one layer fails, subsequent layers prevent catastrophic compromise.

The Concentric Onion Model

[1] Physical Layer → Badges, CCTV, biometric locks
[2] Perimeter Layer → Next-Gen Firewalls, DDoS shielding
[3] Network Layer → VLANs, 802.1X, Micro-segmentation
[4] Host/Endpoint → EDR, AppLocker, Disk Encryption
[5] Application Layer → Input sanitization, WAF, CSP
[6] Data Layer → AES-GCM encryption, DLP, RBAC

Control Categories

  • Preventative: Stops an incident before it occurs (e.g., Firewall rule, password policy).
  • Detective: Identifies and alerts on an ongoing event (e.g., SIEM alert, IDS signature).
  • Corrective: Restores normal state after compromise (e.g., Re-imaging host, backup restore).
  • Compensating: Alternative control when primary cannot be applied (e.g., Network isolation for legacy OS).

06 · STEP-BY-STEP VISUAL WALKTHROUGH

Step-by-Step Operator Setup & Verification

Follow these 6 core visual setup steps to baseline your Kali workstation and verify authorized connectivity.

01

Step 1: Verify Hypervisor Network Adapters & Isolation

Ensure your Kali VM has two network interfaces configured: Adapter 1 for Host/NAT communications, and Adapter 2 or VPN client for lab isolation.

student@kali:~$ ip link show 1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT link/ether 08:00:27:5a:32:bc brd ff:ff:ff:ff:ff:ff
Key Takeaway: eth0 is your primary virtual ethernet adapter. Its state must be UP with a valid MAC address.
02

Step 2: Operator Identity & Privilege Baseline

Confirm user context before executing tasks. Normal tasks run under unprivileged kali / student; root privileges are used strictly when binding low ports or performing raw socket captures.

student@kali:~$ whoami && id student uid=1000(student) gid=1000(student) groups=1000(student),27(sudo),100(users) student@kali:~$ uname -a Linux kali-operator 6.6.9-kali1-amd64 #1 SMP PREEMPT_DYNAMIC Kali 6.6.9-1 (2024-01-08) x86_64 GNU/Linux
03

Step 3: Network Addressing & CIDR Subnet Verification

Inspect IP addresses and subnets on all active interfaces.

student@kali:~$ ip -4 addr show 1: lo: <LOOPBACK,UP,LOWER_UP> inet 127.0.0.1/8 scope host lo 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> inet 192.168.56.20/24 brd 192.168.56.255 scope global eth0
CIDR Explanation: 192.168.56.20/24 means 24 network bits (Subnet Mask: 255.255.255.0), allowing 254 usable hosts (.1 to .254).
04

Step 4: Inspect the Kernel Routing Table

Understand which interface traffic takes when reaching destinations.

student@kali:~$ ip route show default via 192.168.56.1 dev eth0 proto dhcp src 192.168.56.20 metric 100 192.168.56.0/24 dev eth0 proto kernel scope link src 192.168.56.20 metric 100
05

Step 5: Connect Authorized Lab Tunnel (tun0)

Establish the encrypted training tunnel. Once connected, tun0 appears with a 10.10.x.x address.

student@kali:~$ ip addr show tun0 3: tun0: <POINTOPOINT,MULTICAST,NOARP,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UNKNOWN inet 10.10.14.8/24 scope global tun0
06

Step 6: Reachability Probe & ICMP Response Interpretation

Verify network layer connectivity to the authorized target.

student@kali:~$ ping -c 3 10.10.14.1 PING 10.10.14.1 (10.10.14.1) 56(84) bytes of data. 64 bytes from 10.10.14.1: icmp_seq=1 ttl=63 time=24.1 ms 64 bytes from 10.10.14.1: icmp_seq=2 ttl=63 time=23.8 ms 64 bytes from 10.10.14.1: icmp_seq=3 ttl=63 time=24.0 ms --- 10.10.14.1 ping statistics --- 3 packets transmitted, 3 received, 0% packet loss, time 2003ms rtt min/avg/max/mdev = 23.812/23.971/24.102/0.120 ms
Limitation: ICMP replies prove IP routing works. It does NOT prove application-layer services (HTTP/SSH) are open or accessible.

08 · CONCEPTUAL VALIDATION

Knowledge Checkpoints & Scenario Assessments

Test your understanding of security essentials and operational fundamentals before proceeding.

CHECKPOINT 01 · THREAT MODELING
An attacker alters a financial record in a SQL database without authorization. Which core CIA pillar is directly violated?
Explanation: Unauthorized modification of data is an Integrity violation. Confidentiality is about viewing/disclosure, and Availability is about access.
CHECKPOINT 02 · NETWORK ONBOARDING
You run ip addr on Kali and see eth0: 192.168.56.20/24, but no tun0 interface exists. What is the operational situation?
Explanation: tun0 is created dynamically when OpenVPN or WireGuard connects. If it's missing, the VPN tunnel has not been established yet.
CHECKPOINT 03 · COMMAND REASONING
A ping -c 3 10.10.14.1 test receives 3 ICMP replies with 0% packet loss. What can you definitively conclude?
Explanation: ICMP echoes prove Layer 3 (IP) reachability only. Web (HTTP 80) or SSH (22) services operate at Layer 7 and require separate port probes.
