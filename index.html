Program overview

Start from zero. Learn the complete engagement.

This program is designed for learners who are new to VAPT. It builds the technical foundations before introducing reconnaissance, scanning, vulnerability analysis, controlled validation, impact assessment and professional reporting. Students are not expected to know Kali Linux or security tools before Day 1.

Learn

Understand the why

Every tool and technique is introduced with its purpose, prerequisites, limitations and safe use.

Practise

Follow guided labs

Students follow sequenced screenshots, exact steps, expected outputs and troubleshooting checkpoints.

Demonstrate

Build evidence

Each day produces a worksheet, command output, observation, evidence record or report section.

Practical learning environment

Isolated Docker lab environment

The initial practical target is OWASP Juice Shop, an intentionally vulnerable web application deployed locally for training. Students use a Kali workstation as their testing environment. The lab is designed for one learner on one local machine.

Student workstationKali Linux · terminal · browser
↔
Private Docker networkInternal lab communication
↔
OWASP Juice ShopLocal training target · port 3000

Student environment

  • Docker Engine / Docker Desktop
  • Docker Compose
  • Kali Linux workstation container or VM
  • Browser for local application access

Lab operating principles

  • Only the designated local training target is in scope
  • No public target scanning or external exploitation
  • Health checks and reset instructions for repeatable practice
  • Evidence saved by lab and date

Infrastructure package is developed separately from this curriculum homepage. The homepage does not imply that the Docker environment is already running; deployment and verification must be completed on the student's host.

Final assessment

Day 29–30 · Integrated VAPT capstone

NOVACORP — Local Training Engagement

Students receive a fictional engagement brief and assess only the designated local Juice Shop target. They review scope, prepare the lab, collect reconnaissance and scan evidence, analyze selected observations, safely validate an approved training weakness, assess impact and submit a concise report with remediation and retest notes.

Submission pack
  • Scope confirmation
  • Asset and service inventory
  • Evidence register
  • Validated finding report
Presentation
  • Methodology followed
  • What was observed vs proven
  • Impact and limitations
  • Remediation and retest
Non-negotiable lab boundary

Authorized testing only

Training safety rule: Students may test only the local OWASP Juice Shop instance and other assets explicitly provided and authorized by the instructor. Do not scan public IP addresses, employer systems, campus networks, shared infrastructure or third-party services. Stop if the target differs from the assigned asset, unexpected sensitive data appears, or the environment becomes unstable.

Tools are introduced for defensive learning and authorized assessment. Students must preserve evidence, avoid unnecessary data access, respect test boundaries and clean up after each exercise.
